# 更新保护、回滚与针对性修复

适用于当前 `rex-emby-proxy` 定制版。作者源码在 `src/worker.js`，定制功能在外层适配模块。请从当前面板“立即更新”更新；直接在 Cloudflare 覆盖原版代码会绕过这套保护。

## 工作流程

1. 面板验证管理员身份、作者版本标记、禁止降级，并检查回源补丁能否匹配。
2. 独立 Worker `rex-emby-update-guard` 核对当前部署和定制功能。现有功能已异常、权限不足、存在其它更新任务或灰度部署时停止更新。
3. 保存当前 Cloudflare 版本 ID、原始模块代码、Worker 设置，以及配置表的结构和数据；分块写入同一 D1 数据库，并核对代码和配置快照 SHA-256。备份失败时绝不发布。
4. 上传候选版本（此时不切换流量），持久化候选 ID，再发布到 100% 流量。
5. 独立检查器检查新版。页面打开时约每 4 秒推动检查；关闭页面后每分钟的独立 Cron 继续处理。新版传播允许最多 120 秒，从发起切换开始计算；之后若检查仍未通过则自动恢复更新前版本。无页面时最终结果可能要多等一轮 Cron。
6. 回滚时核对当前仍是本次候选版本。发现人工或其它工具已发布新版本时停止操作，避免覆盖别人的部署。回滚请求失败会记录原因，并在后续 Cron 重试，不假报成功。

独立检查器不随作者源码更新。它没有公开 workers.dev 地址，只能经服务绑定调用；管理请求仍验证管理员凭据。更新器与回滚器本身也保留在主 Worker 的多模块更新包中。

## 自动检查的范围

| 报告 ID | 检查内容 | 优先核对文件 |
| --- | --- | --- |
| adapter-version-config-bindings | 上游版本、定制源码指纹、配置摘要、数据库及 Telegram/DNS/统计绑定 | `src/index.js`、`src/self-update.js`、Worker 绑定 |
| panel-speedtest-dns-update-controls | 测速预设、停止、单节点重测、更新保护、固定分享域名等 HTML/脚本标记 | `src/index.js`、`src/entry-probes.js` |
| admin-session | 管理员会话接口仍返回 admin | `src/worker.js` 的鉴权适配 |
| anonymous-access-blocked | 未登录者不能下载面板测速数据 | `src/index.js` |
| speedtest-valid-payload | 已登录者获得完整的 2048 字节测速数据 | `src/entry-probes.js`、`src/index.js` |
| candidate-planner-readonly | 候选规划接口有效；检查使用 planOnly，不创建 DNS | `src/entry-probes.js` |
| telegram-webhook-auth | 无 webhook Secret 的请求被拒绝；不发送 Telegram 消息 | `src/index.js` |
| region-assets | 地区图标能返回 SVG | `src/region-icons.js` |

这些是发布后的关键接口与结构检查，不是每个功能的完整端到端验证。不会发 Telegram 测试消息、修改正式 DNS、创建测速解析、跑大流量下载或登录视频源站。浏览器实际下载速度、源站播放、完整 Telegram 私聊交互及统计平台临时故障，仍需按对应功能人工验收。页面标记完整也不能证明作者新版的所有 JS 都兼容。

## 备份位置和内容

D1 数据库：`rex-emby-proxy-db`。

- `rex_updates`：更新记录、前后版本、状态、检查结果、错误及时间线；不保存 Secret 值。
- `rex_update_chunks`：每个记录的 `code`（原始 multipart 模块代码）、`settings`（部署设置）、`configuration`（配置结构/数据）分块。
- `rex_update_lock`：串行操作锁，防止重复更新与同时回滚。

配置快照包含存在的 `routes`、`app_config`、`rex_bot_owner`，以及兼容用的 `settings`、`config`、`users` 表。**不等于完整 D1 数据库备份**，不含访问日志/历史统计/测速临时表。配置快照可能包含私密地址和密钥，应与数据库同等保护。面板报告只提供摘要和检查结果，不提供快照原文。Secret 由 Cloudflare 保留，不明文写入备份或报告。

代码回滚使用 Cloudflare 原有版本恢复代码和该版本的绑定；不会删除 Worker、改路由、改 DNS 或恢复数据库旧数据。这样不会抹掉更新期间用户的新设置。若作者新版改变数据库结构或数据，代码回滚不保证恢复兼容；应核对快照后针对性恢复，不能自动整库覆盖。Cloudflare 历史版本也有保留限制，故另外保存原始代码快照。

目前不自动清除历史备份，面板展示最近 10 条；较旧记录仍留在 D1，可按 ID 导出。定期关注 D1 容量，再决定归档或清理。

## 面板使用

控制面板的管理与维护区域新增“更新保护 · 自动备份与回滚”：

- “保护已就绪”：独立检查器已有编辑凭据，实际权限还会在更新前核验。
- “尚未启用”：缺少独立检查器的 `CF_API_TOKEN`；此时更新会被阻止。
- “检查通过”：本次关键检查通过，可以下载检查报告；仍可手动回滚本次更新。
- “已回滚”：Cloudflare 已确认旧版本重新部署；另查看 `rollbackChecks` 判断恢复后的接口检查情况。
- “回滚待重试”：尚未确认恢复，不能当作已恢复。独立 Cron 会重试。
- “检测到其它部署，已停止”：有人从其它地方部署过；先检查实际版本，不要盲目强制覆盖。

“下载故障报告”得到只含检查元数据的 JSON。关闭页面不影响后台回滚。若页面失效，从 Cloudflare 查看独立检查器日志及 D1 记录，或用下面的本地导出工具。

## 针对性修复步骤

1. 保留失败记录 ID，下载故障报告；记录 `candidate`、`previousVersions`、失败的 `checks[].id`、`events` 与 `rollbackChecks`。
2. 确认已经回到预期旧版；如果回滚尚未确认，先处理 `recoveryError`（凭据、版本不可用、Cloudflare 网络等）。
3. 用上表定位文件。对照作者新版变动，修改外层适配；保持作者核心源码独立，不把本地旧核心误部署覆盖云端新核心。
4. 导出备份：在项目目录执行 `node scripts/export-update-backup.mjs <记录UUID>`。输出到忽略版本管理的 `backups/update-protection/<UUID>/`，权限为仅当前用户；请勿公开上传。
5. 运行 `npm test`。更新器测试包含两次连续更新后保留定制模块；独立检查器测试包含备份失败、检查失败、回滚失败重试、并发锁和人工部署保护。
6. 维护独立检查器时运行 `npm run deploy:guard`；维护主适配器用 `npm run deploy`。这两条维护部署命令不经过网页自动备份，应先另行保存当前版本和数据库快照。
7. 修复好后再从受保护的网页更新入口发布，形成一个新记录。保留旧失败记录，便于比较同一失败项是否修好。

如主面板完全不能打开，Cloudflare → Workers → 主 Worker → Deployments 中选择 `previousVersions` 的版本 ID 恢复。不要改成作者原版、不要删除数据库/Secret。如果历史版本已不可用，用备份代码和设置经过本地审查后重新部署；导出的原始 multipart 不是单个可直接粘贴的 JS 文件。

## 首次启用和维护凭据

独立检查器需要以下既有绑定：`DB`、指向主 Worker 的 `TARGET` 服务绑定、`CF_ACCOUNT_ID`、`CF_WORKER_NAME`，以及两个 Secret：

- `ADMIN_TOKEN`：与主面板现有管理员凭据相同，仅用于私有服务调用和检查；不新增公开登录入口。
- `CF_API_TOKEN`：该账号所需的 Workers Scripts 编辑权限，用于读取当前代码/设置/版本、上传版本及切换部署。不需要 DNS 编辑或 Analytics 权限。凭据创建/授权应由账号主人确认；不要放进代码、报告或 Git。

主 Worker 绑定 `UPDATE_GUARD` 指向检查器。凭据只放检查器，主 Worker 不再需要 `CF_API_TOKEN`。设置 Secret 后独立检查器不会公开它；可在面板刷新记录确认状态，再用现有代码做一次受保护的同版本更新和手动回滚演练。

参考：[Cloudflare 版本回滚说明](https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/)、[部署 API](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/deployments/)。
